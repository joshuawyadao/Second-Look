# Working on Second Look

Second Look is a native iPhone project for private two-person checklists and human photo review. Read `README.md`, `docs/Product-Brief.md`, `docs/Product-Spec.md`, and relevant docs before changes. The October 2, 2026 handoff is preserved in those canonical docs and `docs/Roadmap.md`.

- Respect milestone boundaries. Milestones 0–1 contain local storage and Debug-only simulated roles/evidence/services. Milestone 2 adds authenticated private shared state and remains in progress until its full exit checks are verified. Real photos, remote uploads, push, real deletion, unpairing, and distribution are later work. Do not describe synthetic evidence or local-stack tests as hosted or real-media functionality.
- Keep domain rules and local atomic persistence in dependency-free `SecondLookCore`; the Milestone 2 Swift server reuses those rules and owns authenticated commands, while private Postgres RPCs own connected atomic writes. Keep platform/UI code in `SecondLook/`. The checked-in Xcode project is the native workflow. iOS 17 is a provisional target, not verified device support.
- Keep synthetic fixtures, role selection, and service response controls behind `SECONDLOOK_DEMO`, separate from Release identity/storage. The Debug localhost-only synthetic-evidence route is test metadata, not an image upload or production API. Never use a role picker as authorization. Preserve exact submission-version checks, fixed run roles, snapshot isolation, and terminal closure.
- For connected changes, derive actor identity from verified Supabase Auth access tokens on the server, require an explicit two-account allowlist and membership, and use server-side revisions and request-bound receipts. The iPhone may hold public endpoints/keys and Keychain credentials, never a service-role key. Clear or isolate protected state on account change; old asynchronous responses must not restore it.
- Run `./scripts/verify-repository.sh`, `swift test`, and `./scripts/verify-native.sh` for relevant app changes; run the local shared-state integration workflow when changing that boundary. Discover available simulator destinations. Document failed or unavailable checks honestly and add meaningful behavior tests. Local Supabase Auth/Postgres/HTTP checks do not establish hosted or two-device acceptance.
- Preserve durable decisions in canonical product/architecture/decision docs. `docs/Implementation-Plan.md` is replaceable task tracking. Update `docs/Verification.md` with actual evidence and limitations.
- Use synthetic fixtures only. Never publish credentials, household photos, private participant data, local app state, or generated build/test artifacts. There is no default age-based photo expiry; reminders and optional unreviewed timeout are independent, and no connected scheduler exists in M2.
- Stage only task-owned files and keep Git operations sequential. Use feature branches and pull requests for protected `main`; do not open a PR or merge unless requested. Keep meaningful local checkpoints and push the intended existing remote at final save when authorized.
- Delegate bounded responsibilities with explicit ownership, preserve others' edits, and integrate results. Do not assign unrelated project specialists to this app.

These instructions are tool-neutral; contributions do not require proprietary tools or personal skills.
